# GOAL-001 — первая сборка и подготовка Redmi

## Результат

Получить действительно собираемый Android-проект и APK для личной установки на Redmi Note 9 Pro.
Не ограничиваться чтением документации, предложением команд или повторением исходного плана.
Нужны выполненная сборка, исправления выявленных интеграционных ошибок и конкретный RESULT.md.
В исходной среде не было .NET/Android SDK: компиляция, native linking, ML Kit и TTS не проверялись.

## Работа

1. Прочитать AGENTS.md, README, docs/VALIDATION.md и BUILD_WINDOWS.md. Выполнить
   `scripts/Doctor.ps1`, определить установленные .NET/Android workload, SDK, JDK и ADB.
   Пользователь разрешил установить недостающие Android-зависимости. Использовать
   Visual Studio Installer либо Setup-Android.ps1; не повреждать существующее окружение.
2. Подготовить оригинальные native assets и атрибуцию через Get-BuildAssets.ps1.
   При невозможности загрузки проверить официальный URL/версию/sidecar; не пропускать
   проверку целостности и не генерировать фиктивный логотип/пустой libvosk.so.
   Осмотреть выбранный powered-by бейдж. Зафиксировать реальный Vosk SHA-256 и источник.
3. Restore, запустить Core.Smoke, скомпилировать Android и получить подписанный debug APK.
   Проверить пространства имён и сигнатуры привязок ML Kit, AudioRecord и TextToSpeech.
   Исправлять реальную интеграцию по ошибкам компилятора, без заглушек распознавания/перевода.
   Проверить классы registrar после упаковки, все зависимости libvosk.so, ABI и linked assets.
4. Проверить Windows PowerShell-скрипты в реальном Windows. Исправить несовместимости.
   Поддержать существующий VS SDK/JDK. Build.ps1 должен завершаться ошибкой при провале
   и не выдавать старый APK за новую сборку. Сохранить NuGet lockfiles после успешного restore.
5. Если ADB видит один разрешённый телефон, установить через Install.ps1 без удаления данных.
   Зафиксировать реальную модель, Android/API и RAM. Не подделывать согласие пользователя
   на USB-отладку, доступ к микрофону или установку системного голоса.
   Запустить приложение и пройти доступные пункты TEST_PLAN_REDMI.md.
   При отсутствии устройства не ожидать его бесконечно: закончить всё доступное,
   выпустить APK и пометить аппаратную часть NOT_TESTED.
6. Обновить README/VALIDATION по фактическому состоянию; заполнить RESULT.md.

## Особо проверить

- Отсутствующий русский/польский пакет; первый download; обрыв; SHA mismatch; мало места.
- Вызов Translate не запускает скрытую загрузку. Отсутствие сети не маскируется облачным fallback.
- Оба языка распознаются реальным микрофоном; польская модель действительно загружается.
- TTS-громкость, выбор локального голоса, его ошибки и окончание utterance.
- Сворачивание/отмена не освобождают native model раньше времени. Нет capture↔TTS петли.
- Поздние callbacks и быстрые повторные нажатия не запускают несколько операций.
- В авиарежиме + Wi-Fi off после холодного запуска выполнить минимум 10 реплик на язык.
- Переключение языков: холодная загрузка модели, время до начала слушания,
  время от конца речи до первой слышимой озвучки, P50/P95 и пиковая память.
  При отсутствии реальных измерений написать NOT_MEASURED, а не придумать числа.

## Приёмка и отчёт

В `docs/tasks/GOAL-001-FIRST-DEVICE/RESULT.md` указать отдельно:
`SOURCE_BUILD`, `CORE_SMOKE`, `APK_PACKAGED`, `DEVICE_LAUNCH`, `OFFLINE_RU_TO_PL`,
`OFFLINE_PL_TO_RU`, `OFFLINE_TTS_RU_PL`, `LATENCY_MEMORY`.
Разрешённые статусы: PASS, FAIL, NOT_TESTED/NOT_MEASURED с причиной.

Указать путь `artifacts/Mostik-0.1.0-debug.apk`, SHA-256 и отладочную подпись.
Если сборка не удалась, показать первую реальную блокирующую ошибку, всё исправленное
и точный остаток; не объявлять задачу полностью выполненной.

## Git / публикация результата

Пользователь явно разрешил Git-операции для этой задачи и требует публикацию проекта.
Репозиторий: `https://github.com/kpCat/Mostik.git`.
Целевая ветка: `master`.

1. В начале зафиксировать `git status`, текущую ветку и `git remote -v`.
2. Работать только с проектом в `C:\Users\ZBook\Mostik\`.
3. Если `origin` отсутствует — добавить `https://github.com/kpCat/Mostik.git`.
   Если он указывает на другой репозиторий — привести `origin` к явно указанному URL
   и отметить это в RESULT.md.
4. Не использовать `reset --hard`, `clean -fd`, rebase опубликованной истории,
   force-push и любые операции, способные потерять пользовательские изменения.
5. Перед commit просмотреть staged-файлы. Не коммитить секреты/токены, `.tools`,
   Android SDK/JDK, скачанные модели, build cache, `bin/obj`, APK/AAB, keystore,
   logcat/binlog или другие локальные/персональные артефакты.
6. Закоммитить исходники, документацию, lockfiles и честный RESULT.md одним понятным
   коммитом (для первой публикации допустимо сообщение:
   `Initial Mostik RU-PL offline translator`).
7. Даже если аппаратные проверки на Redmi имеют статус NOT_TESTED, но исходники и
   доступные проверки завершены, commit/push всё равно выполнить.
   Если сборка заблокирована внешней причиной, сохранить честный RESULT.md,
   закоммитить текущие исправления и также попытаться push, не скрывая FAIL.
8. Выполнить `git push -u origin master`.
9. После push проверить локальный `HEAD` и удалённый `refs/heads/master`; SHA должны
   совпасть. В RESULT.md записать commit SHA и результат push.
10. Если GitHub отклоняет push из-за авторизации/политики — не применять force и не
    вставлять credentials в файлы или команды отчёта; привести точную ошибку и
    оставить локальный commit готовым к повторному push.
